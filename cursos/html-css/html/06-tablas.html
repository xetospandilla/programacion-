Lección 06: Tablas

Cómo presentar datos en filas y columnas con etiquetas semánticas.

Objetivos

  • Construir una tabla de datos con table, caption, thead, tbody, tr, th y td.
  • Diferenciar encabezados (th) de datos (td).
  • Saber cuándo NO usar tablas (maquetar no es tabular).

Conocimientos previos

Las lecciones anteriores: estructura mínima (intro), encabezados y párrafos (01), y rutas relativas (05), porque aquí usaremos enlaces e imágenes.

1. La tabla en tres bloques

Una tabla semántica separa tres zonas:

  • <caption>: el título o leyenda de la tabla. Se coloca justo después de la etiqueta de apertura.
  • <thead>: la fila (o filas) de encabezados, con <th>.
  • <tbody>: las filas de datos, con <td>.

Cada fila es un <tr> (table row). Dentro de él van celdas: <th> (table header) para encabezados y <td> (table data) para valores.

<!-- Estructura básica de una tabla -->
<table>
    <caption>Ejemplo: países y capitales</caption>
    <thead>
        <tr>
            <th scope="col">País</th>
            <th scope="col">Capital</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <td>España</td>
            <td>Madrid</td>
        </tr>
        <tr>
            <td>Argentina</td>
            <td>Buenos Aires</td>
        </tr>
    </tbody>
</table>

Así se ve en el navegador:

Ejemplo: países y capitales
País Capital
España Madrid
Argentina Buenos Aires

2. Por qué th y scope importan

<th> no solo se ve en negrita: comunica a los lectores de pantalla qué es cada columna, de modo que una persona ciega puede navegar la tabla entendiendo qué dato hay en cada cruce. El atributo scope="col" (o scope="row") refina esa relación: dice si el encabezado corresponde a toda una columna o a toda una fila.

<tr>
    <th scope="row">España</th>
    <td>Madrid</td>
</tr>

Aquí "España" es la etiqueta de SU fila; Madrid es un dato.

3. Un ejemplo con datos reales: tabla de horarios

<table>
    <caption>Horario de la asignatura</caption>
    <thead>
        <tr>
            <th scope="col">Hora</th>
            <th scope="col">Lunes</th>
            <th scope="col">Miércoles</th>
        </tr>
    </thead>
    <tbody>
        <tr>
            <th scope="row">09:00</th>
            <td>HTML</td>
            <td>CSS</td>
        </tr>
        <tr>
            <th scope="row">10:30</th>
            <td>Práctica</td>
            <td>Práctica</td>
        </tr>
    </tbody>
</table>
Horario de la asignatura
Hora Lunes Miércoles
09:00 HTML CSS
10:30 Práctica Práctica

Las horas son th scope="row": encabezan su fila cuando el lector recorre la tabla en horizontal.

Para unir celdas existen colspan y rowspan (por ejemplo, una celda que ocupe dos columnas con colspan="2"). Se usan con moderación: complican la lectura para lectores de pantalla.

4. Cuándo NO usar tablas

Las tablas son para datos tabulares: valores que tienen sentido cruzando filas y columnas (precios, horarios, resultados...).

MAL — usar una tabla para maquetar: en los años 90 se colocaban imágenes y textos con tablas invisibles. Hoy es una mala práctica: el contenido se vuelve difícil de leer, de adaptar a móviles y de mantener.

<!-- Esto es un error de diseño, no una tabla -->
<table>
    <tr>
        <td><img src="logo.svg" alt="Logo"></td>
        <td>Menú de navegación</td>
    </tr>
</table>

BIEN — cada cosa en su sitio: el logo y la navegación van en etiquetas semánticas (<header>, <nav>; se ven en la lección de semántica) y la maquetación se hace con CSS. Las tablas quedan reservadas para los datos.

Errores frecuentes y cómo corregirlos

  • Olvidar thead/tbody: el navegador lo tolera, pero la estructura semántica (qué es encabezado y qué es dato) se pierde para la accesibilidad.
  • Encabezados con td: usar <td> en la primera fila no comunica que son títulos. Usa <th>.
  • Tablas anidadas (una dentro de otra): muy difícil de leer. Extrae los datos a una sola tabla o divide la información.
  • Maquetar con tablas: ver el apartado 4. Si la tabla solo existe para "colocar cosas", la solución es CSS, no más tablas.
  • Celdas sin contenido: una celda vacía para "empujar" el diseño. Si no hay dato, la fila/columna no debería existir (o usa colspan bien aplicado).

Ejercicios

Crea un archivo mi-tabla.html para cada ejercicio.

  1. Fácil — clasificación: construye una tabla con caption "Clasificación de la liga" y columnas Posición, Equipo y Puntos; tres filas de datos.
  2. Medio — presupuesto: tabla con thead (Concepto, Precio) y tbody con tres filas; añade una fila final con "Total" como th scope="row". El precio total no tiene que calcularse: es una celda más.
  3. Difícil — fusión: usa colspan="2" para que una celda "Usuario invitado" ocupe dos columnas en una tabla de acceso. Revisa que las filas siguientes sigan teniendo el número correcto de columnas.

Soluciones razonadas

Intenta cada ejercicio antes de leer la solución.

Ejercicio 1

<table>
    <caption>Clasificación de la liga</caption>
    <thead>
        <tr><th scope="col">Posición</th><th scope="col">Equipo</th><th scope="col">Puntos</th></tr>
    </thead>
    <tbody>
        <tr><td>1</td><td>Equipo A</td><td>21</td></tr>
        <tr><td>2</td><td>Equipo B</td><td>18</td></tr>
        <tr><td>3</td><td>Equipo C</td><td>15</td></tr>
    </tbody>
</table>

Los encabezados van en thead (con th) y los datos en tbody (con td).

Ejercicio 2

<tr>
    <th scope="row">Total</th>
    <td>95 €</td>
</tr>

"Total" es la etiqueta de esa fila, por eso es th scope="row"; el importe es el dato.

Ejercicio 3

<tr>
    <td colspan="2">Usuario invitado</td>
</tr>

colspan="2" hace que esta celda ocupe el ancho de dos columnas. Las filas siguientes deben seguir teniendo dos celdas normales para que la cuadrícula no se descoloque.

Resumen y autoevaluación

Las tablas presentan datos tabulares con una estructura semántica: caption (título), thead (encabezados con th), tbody (datos con td) y filas tr. El atributo scope conecta los encabezados con sus filas o columnas. Las tablas NO sirven para maquetar páginas.
