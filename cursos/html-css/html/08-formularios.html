Lección 08: Formularios

Los formularios recogen datos de quien visita la página: textos, contraseñas, fechas, elecciones... Aquí veremos cada elemento, sus atributos y un formulario demostrativo que funciona sin backend.

Objetivos

  • Identificar las partes de un formulario: form, label, input, textarea, select, button.
  • Dominar los atributos name, value y required, y los tipos de input.
  • Agrupar campos con fieldset y legend.
  • Usar la validación nativa del navegador.
  • Entender qué pasa al enviar un formulario sin backend.

Conocimientos previos

Las lecciones de semántica y encabezados. Los formularios funcionan con HTML puro; el procesado del servidor sale del alcance de este bloque.

1. ¿Qué le ocurre al formulario al enviarlo?

Un formulario sin backend (sin un programa en el servidor que reciba los datos) hace esto: el navegador primero valida los campos y, si todo es correcto, recarga la página llevando los datos en la barra de direcciones cuando method="get". Por ejemplo, al enviar el campo name="usuario" con el valor "ana", la URL acaba en ?usuario=ana. Así puedes ver qué se envía, sin necesitar ningún servidor.

Con method="post" los datos viajarían "dentro" de la petición, invisibles en la URL; pero sin un servidor que la procese no verás nada. Por eso, en esta lección todos los ejemplos funcionales usan get.

2. La etiqueta form

<form action="" method="get">
    ...
</form>
  • action: a qué dirección se envían los datos. Vacío significa "esta misma página".
  • method: get (datos visibles en la URL) o post (ocultos, para datos sensibles o largos).

3. label: la etiqueta del campo

Cada campo debe tener su <label> asociado con for, y el campo el mismo valor en id. Al hacer clic en el texto de la etiqueta, el cursor salta al campo; los lectores de pantalla anuncian el nombre del campo.

<label for="nombre">Nombre</label>
<input type="text" id="nombre" name="nombre">

4. input: los tipos y sus atributos

<input> es la etiqueta vacía más versátil del formulario. El atributo clave es type:

  • text: texto libre de una línea.
  • email: texto que, además, debe tener formato de correo.
  • password: como text pero con los caracteres ocultos.
  • number: solo números (con min/max opcionales).
  • date: fecha con selector del navegador.
  • checkbox: casilla de marcar (por ejemplo, aceptar condiciones).
  • radio: elegir una opción entre varias.
  • file: seleccionar un archivo local.
  • submit: botón que envía el formulario.
  • reset: botón que limpia los campos.

Y los atributos más usados:

  • name: nombre lógico del campo. Es el identificador que recibe el servidor (o el que ves en la URL); sin name, el valor no se envía.
  • value: valor por defecto (o el que viaja, para radio y checkbox).
  • required: campo obligatorio; el navegador no envía si está vacío.
  • placeholder: texto de ejemplo que desaparece al escribir. No sustituye al label.
  • readonly: se ve pero no se edita (sí se envía).
  • disabled: desactivado y no se envía.

Ejemplo vivo con varios tipos:

<form action="" method="get">
    <p><label>Correo: <input type="email" name="correo" required
                 placeholder="tunombre@ejemplo.com"></label></p>
    <p><label>Contraseña: <input type="password" name="clave"></label></p>
    <p><label>Edad: <input type="number" name="edad" min="0" max="120"></label></p>
    <p><input type="checkbox" id="aviso" name="aviso">
        <label for="aviso">Acepto el aviso legal</label></p>
    <p><input type="submit" value="Enviar"></p>
</form>

Prueba a enviarlo sin correo: el navegador bloquea el envío y muestra el mensaje de validación nativa.

5. textarea y select

<textarea> es el campo multilínea. No es vacía: el contenido por defecto va entre las etiquetas.

<label for="mensaje">Mensaje:</label>
<textarea id="mensaje" name="mensaje" rows="4" cols="40">
Texto inicial opcional
</textarea>

<select> es la lista desplegable; cada opción va en <option> (el atributo de cada opción es su value; el texto visible va dentro).

<label for="pais">País:</label>
<select id="pais" name="pais">
    <option value="es">España</option>
    <option value="ar">Argentina</option>
    <option value="mx">México</option>
</select>

6. button: submit, reset y button

El elemento <button> admite contenido propio (texto, iconos) y su atributo type decide su papel:

  • type="submit" (por defecto): envía el formulario.
  • type="reset": vuelve los campos a su valor inicial.
  • type="button": no hace nada solo; se usa con JavaScript (como en los ejercicios del curso de JavaScript).
<button type="submit">Enviar ahora</button>
<button type="reset">Borrar</button>

7. Agrupar con fieldset y legend

Para formularios largos, <fieldset> agrupa campos y <legend> pone el título del grupo. Mejoran el orden visual y la accesibilidad (el lector de pantalla anuncia el grupo al entrar en él).

<fieldset>
    <legend>Datos personales</legend>
    <label for="nombrefs">Nombre:</label>
    <input type="text" id="nombrefs" name="nombre">
    <label for="emailfs">Correo:</label>
    <input type="email" id="emailfs" name="correo">
</fieldset>

8. Validación nativa y accesibilidad

Sin escribir JavaScript, el navegador ya valida si usas los atributos correctos:

  • required: campo obligatorio.
  • type="email": formato de correo.
  • min/max (en number o date): límites.
  • minlength/maxlength: longitud del texto.
  • pattern: una expresión regular, por ejemplo pattern="[0-9]{5}" para un código postal de cinco cifras.

Para que todo el mundo pueda rellenar el formulario:

  • Cada campo con su label asociado (nunca solo placeholder como etiqueta).
  • Grupos de radio/checkbox con fieldset y legend cuando tengan un título común.
  • No uses el color como única señal de error; el navegador también muestra texto.

Condiciones y preferencias

Prueba guiada: deja el correo vacío y pulsa "Enviar": el navegador marca el campo obligatorio. Rellena el correo con texto sin @ y vuelve a enviar: ahora avisa del formato. Cuando todo sea válido, observa la barra de direcciones: verás ?username=...&useremail=.... Eso es lo que viajaría a un servidor real.

Errores frecuentes y cómo corregirlos

  • Campo sin name: su valor no se envía. Revisa que todos los campos que quieres enviar tengan name.
  • label sin for o id distinto: el clic no activa el campo y la accesibilidad se rompe. Haz coincidir for del label con id del input.
  • Varios radio incompatibles: para que elegir una opción desmarque las demás, todos deben tener el MISMO name.
  • Botón <a> dentro de <button>: un botón de enlace se escribe con <a> (o <button type="button"> + JS), no anidando un enlace dentro de un submit.
  • Depender solo de placeholder: el texto de ejemplo desaparece al escribir y no sirve como etiqueta accesible. Usa label.
  • Validar solo con JavaScript: la validación nativa cubre los casos comunes sin código. Combínala con las reglas del servidor, no con scripts innecesarios.

Ejercicios

Crea mi-formulario.html.

  1. Fácil — registro: formulario con nombre (text, obligatorio), correo (email, obligatorio) y botón submit. Cada campo con su label y name.
  2. Medio — agrupar y elegir: añade un fieldset "Preferencias" con una lista desplegable (select de tres colores) y dos radios del mismo name ("Sí"/"No").
  3. Difícil — validación completa: añade un campo de comentarios (textarea) con maxlength="200", un número con min/max, y comprueba en el navegador todos los mensajes de validación nativa.

Soluciones razonadas

Intenta los ejercicios antes de leer esto.

Ejercicio 1

<form action="" method="get">
    <label for="nombre">Nombre:</label>
    <input type="text" id="nombre" name="nombre" required>
    <label for="correo">Correo:</label>
    <input type="email" id="correo" name="correo" required>
    <button type="submit">Registrarme</button>
</form>

El for del label coincide con el id del input; name está en cada campo.

Ejercicio 2

<fieldset>
    <legend>Preferencias</legend>
    <label for="color">Color favorito:</label>
    <select id="color" name="color">
        <option value="azul">Azul</option>
        <option value="verde">Verde</option>
        <option value="rojo">Rojo</option>
    </select>
    <p><input type="radio" id="si" name="boletin" value="si">
        <label for="si">Sí</label>
        <input type="radio" id="no" name="boletin" value="no">
        <label for="no">No</label></p>
</fieldset>

Los radios comparten name="boletin": por eso elegir uno desmarca el otro.

Ejercicio 3

<label for="comentario">Comentarios:</label>
<textarea id="comentario" name="comentario" rows="4" maxlength="200"></textarea>

<label for="edad2">Edad:</label>
<input type="number" id="edad2" name="edad" min="0" max="120">

Prueba a superar 200 caracteres o poner 130 años: el navegador mostrará su mensaje antes de enviar.

Resumen y autoevaluación

Un formulario se compone de form (con action y method), campos (input de muchos type, textarea, select), etiquetas label asociadas, botones button y grupos fieldset/legend. Los atributos name, value y required definen qué se envía y qué se exige; la validación nativa evita envíos incorrectos sin JavaScript. Sin backend, con method="get", los datos aparecen en la URL.
