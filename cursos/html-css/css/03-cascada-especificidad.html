Lección 13: Cascada, herencia y especificidad

Tres reglas del juego que deciden, cuando varias reglas apuntan al mismo elemento, cuál gana. Sin ellas, cualquier hoja de estilos sería un caos.

Objetivos

  • Explicar qué es la cascada y por qué el orden de aparición importa.
  • Distinguir qué propiedades se heredan y cuáles no.
  • Calcular la especificidad de un selector (versión simplificada).
  • Entender !important y por qué conviene evitar abusar de él.

Conocimientos previos

La introducción a CSS (anatomía de una regla) y los selectores: esta lección decide qué pasa cuando varios chocan.

1. La cascada y el orden de aparición

«Cascada» significa que las reglas caen unas sobre otras, y que ante el mismo selector con la misma importancia, gana la última declarada (la que aparece más abajo en el archivo, o más tarde en una hoja enlazada después).

/* Dos reglas idénticas en especificidad: gana la última */
.demo-cas .orden-a { color: #1f4e79; }
.demo-cas .orden-a { color: #b5332e; }

Este párrafo está pintado por la SEGUNDA regla (burdeos): misma especificidad, gana la última.

El mismo principio aplica entre hojas: si dos <link> compiten, el que va más abajo en el head manda (a igualdad de especificidad).

2. Herencia

Muchas propiedades de texto (color, font-family, font-size, line-height, text-align...) se heredan: si se las pones a un padre, sus hijos la usan si ellos no la definen.

.demo-cas .hereda {
    color: #2e7d32;           /* bajará a hijos y nietos */
    font-family: Georgia, serif;
}

Yo soy verde y en Georgia. Yo soy su hijo: heredo el color y la fuente. El borde no se hereda: es mío y va a mi nombre.

Lo que NO se hereda: márgenes, bordes, fondos, anchuras... Piensa por qué: un borde en el padre no debería repetirse en cada hijo. A los hijos se les da la propiedad de forma explícita.

3. Especificidad

Cuando dos reglas distintas apuntan al mismo elemento, no gana la última: gana la más específica. Se puntúa con tres cifras (id, clase, etiqueta):

Selector Puntos (id, clase, etiqueta)
p (0, 0, 1)
.demo-cas p (0, 1, 1)
.sp (0, 1, 0)
#elem-sp (1, 0, 0)

Se comparan las cifras de izquierda a derecha: un ID gana a cualquier número de clases; una clase gana a cualquier número de etiquetas.

.demo-cas p.sp   { color: #1565c0; }  /* (0,1,1) */
.demo-cas #elem-sp { color: #b5332e; }  /* (1,0,0): gana */

Un párrafo con clase y con ID. La regla del ID gana aunque la de la clase va también sobre él: 1 en la primera cifra vale más que 0.

Consecuencia práctica: si abusas de IDs para estilos, luego «necesitas» IDs aún más específicos o !important para tocarlos. Por eso se estila con clases: toda la especificidad se mantiene baja y predecible.

4. !important: la excepción que rompe la cascada

Una declaración con !important gana a cualquier otra, sea cual sea su especificidad:

.demo-cas p.imp     { color: #1565c0; }
.demo-cas #elem-imp { color: #2e7d32; }
.demo-cas .gana-todo { color: #7b1fa2 !important; }

Tengo etiqueta, clase e ID apuntándome; pero la declaración con !important (morada) gana a todas.

¿Por qué se evita? Porque deja de poder razonar el resultado (la cascada ya no decide) y cualquier regla futura tendrá que competir con !important... añadiendo más !important. Úsalo solo como último recurso y documentado, casi nunca en hojas de tu propio proyecto.

Errores frecuentes y cómo corregirlos

  • «Puse la regla y no cambia nada»: casi siempre es especificidad: otra regla con más puntos gana. Súbele la especificidad a la tuya (clase más concreta) en lugar de añadir !important.
  • Esperar que un borde «se herede»: no se hereda. Pon el borde en cada elemento que lo necesite.
  • Creer que el orden importa más que la especificidad: primero se compara la especificidad; solo si es igual decide el orden.
  • IDs para todo: dispara la especificidad y encadena peleas de reglas. Clases, por defecto.

Ejercicios

Parte de mi-cascada.html con estructura mínima.

  1. Fácil — orden: escribe dos reglas sobre la misma clase `.mensaje` con distinto color. ¿Cuál gana? Compruébalo y anota en un comentario la respuesta.
  2. Medio — especificidad: da color a un párrafo con p, con clase y con ID, y comenta cuál gana y «cuántos puntos» tiene cada regla.
  3. Difícil — herencia + especificidad: padre con color e hijo con su propia clase que cambia solo su color. ¿El nieto de qué color sale? Razónalo y verifícalo en el navegador.

Soluciones razonadas

Intenta los ejercicios antes de leer esto.

Ejercicio 1

.mensaje { color: #1f4e79; }
.mensaje { color: #b5332e; }   /* gana esta: misma especificidad, última */

Ejercicio 2

p { color: #999; }            /* (0,0,1) */
.palabra { color: #1565c0; }   /* (0,1,0) */
#unica { color: #b5332e; }     /* (1,0,0): gana */

Ejercicio 3

.padre { color: #2e7d32; }        /* verde, se hereda */
.nieto { color: inherit; }       /* explícito: hereda del padre */
/* Un nieto sin regla propia heredaría el verde de su padre;
   con la clase .nieto que solo usa inherit, también verde.
   Si la clase del hijo pone otro color, el hijo cambia y el
   nieto sigue verde (hereda del padre directo). */

Resumen y autoevaluación

La cascada decide el ganador entre reglas: primero !important, luego la especificidad (id > clase > etiqueta) y, a igualdad, la última declarada. Algunas propiedades se heredan (texto) y otras no (bordes, márgenes). Mantén la especificidad baja con clases y evita !important salvo excepción justificada.
