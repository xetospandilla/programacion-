Lección 22: Diseño responsive

Que la página se vea bien en cualquier ancho: más pequeña o más grande. Mobile-first, media queries, anchos fluidos e imágenes que no desbordan.

Objetivos

  • Explicar el enfoque mobile-first.
  • Escribir @media y decidir entre min-width y max-width.
  • Usar anchos fluidos e imágenes adaptables.
  • Evitar los errores clásicos del responsive.

Conocimientos previos

La meta viewport (vista en la introducción de HTML) y las unidades relativas de la lección 04 (%, vw, rem): el responsive es su aplicación.

1. El enfoque mobile-first

Se escriben primero los estilos para la pantalla más pequeña (una columna, texto cómodo) y luego se añaden los mejorados dentro de @media (min-width: ...) conforme la pantalla crece. Ventajas: el móvil, que es lo más limitado, nunca se «rompe»; y el CSS base queda más corto.

/* BASE (móvil): una sola columna, sin media query */
main article { margin-bottom: 0.6rem; }

/* MEJORA (pantallas de 560px o más): dos columnas */
@media (min-width: 560px) {
    main { display: grid; grid-template-columns: 1fr 1fr; gap: 0.6rem; }
}

Demostración en vivo (reduce y ensancha la ventana):

Artículo 1: los estilos base valen para móvil.
Artículo 2: desde 560px esta zona se pone en dos columnas.
Artículo 3: cada artículo se apila en el móvil.
Artículo 4: el salto lo da la media query.

Con max-width se hace al revés (estilos grandes primero y «descender»); mobile-first con min-width es la práctica recomendada hoy.

2. Anchos fluidos e imágenes adaptables

Los anchos en % (o fr etc.) respiran con su contenedor; evitar width fijas en px para zonas importantes:

30%
70% (juntos suman 100%)

Las imágenes se vuelven adaptables con dos reglas:

img { max-width: 100%; height: auto; }

3. La meta viewport, imprescindible

Sin ella, los móviles muestran la página «de escritorio» diminuta y con zoom. Esta meta ya está en todas las lecciones del curso:

<meta name="viewport" content="width=device-width, initial-scale=1.0">

Errores frecuentes y cómo corregirlos

  • Página diminuta en móvil: falta la meta viewport en el head. Añádela.
  • Anchos fijos en px: una columna de 300px desborda un móvil de 320px. Usa %, fr, vw o max-width con min.
  • Imagen que se sale: sin max-width: 100%. Añádesela (global o por clase).
  • Media queries al revés: con mobile-first, la pantalla pequeña NO lleva media query; los breakpoints son aumentos (min-width).
  • Breakpoints de «cada modelo de móvil»: diseña por contenido (560px aquí; 768, 1024...), no por cada dispositivo.
  • Texto que no se reescala: prefiere rem para que el usuario pueda agrandarlo; evita tamaños fijos mínimos.

Soluciones razonadas

Intenta los ejercicios antes de leer esto.

Ejercicio 1

/* nada que añadir: el flujo normal ya apila los artículos */

Ejercicio 2

@media (min-width: 600px) {
    section { display: grid; grid-template-columns: 1fr 1fr; gap: 1rem; }
}

Ejercicio 3

.fila { display: flex; flex-wrap: wrap; gap: 1rem; }
.fila img { max-width: 100%; height: auto; flex: 1 1 200px; }
.fila p   { flex: 1 1 200px; }

La imagen y el texto se reparten el ancho y, en pantallas pequeñas, se apilan en vertical porque el wrap los baja.

Resumen y autoevaluación

Responsive = base mobile-first + mejoras con @media (min-width) + anchos fluidos + imágenes con max-width: 100% + la meta viewport. Los breakpoints se eligen por contenido, no por dispositivos.
