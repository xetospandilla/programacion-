Lección 25: Accesibilidad y depuración

La última lección de CSS del curso: hacer que las páginas se puedan usar por todo el mundo (contraste, foco, movimiento) y el método para encontrar por qué «un estilo no funciona».

Objetivos

  • Aplicar contraste suficiente y no usar solo el color.
  • Mantener el foco visible y respetar prefers-reduced-motion.
  • Usar las herramientas de desarrollo del navegador.
  • Depurar CSS con un método, no por prueba y error.

Conocimientos previos

Las lecciones de cascada y especificidad, estados y foco y variables: aquí se aplican a casos reales.

1. Contraste y «no solo color»

Las pautas WCAG (AA) piden un contraste de al menos 4,5:1 para texto normal (3:1 para texto muy grande). Texto claro sobre fondo claro o gris sobre gris es ilegible para mucha gente, incluso sin discapacidad visual.

Bien (contraste alto):

Texto casi negro sobre blanco: ratio alto, legible.

Mal (solo como ejemplo mental, no lo reproduzcas): gris claro sobre gris claro casi no se ve. Recuerda también la regla de la lección de estados: la información nunca se comunica UNICAMENTE con color (añade texto, icono o forma).

Para medir el contraste puedes usar el selector de color de DevTools, que muestra el ratio y si cumple WCAG.

2. Foco visible y movimiento reducido

Foco: quien navega con teclado necesita ver dónde está. Estilo un anillo en :focus-visible y no elimines el outline sin alternativa:

Movimiento reducido: mucha gente (con vértigo, epilepsia o sensibilidad al movimiento) prefiere que no haya animaciones. El navegador lo comunica con prefers-reduced-motion. Mira el pulso de abajo: si tu sistema tiene «reducir movimiento» activado, el pulso se desactiva por el media query:

Este texto pulsa suavemente — y no pulsa si tu sistema pide movimiento reducido.

@media (prefers-reduced-motion: reduce) {
    .pulso { animation: none; }
    /* patrón general: * { animation: none; transition: none; } */
}

3. Las herramientas de desarrollo del navegador

En cualquier navegador, clic derecho sobre un elemento → «Inspeccionar» (F12 / Ctrl+Shift+I abre las DevTools). Lo esencial para CSS:

  • Inspector/elementos: muestra el HTML y, en la pestaña «Estilos», cada regla que afecta al elemento, con las que ganan y las tachadas (y por qué orden).
  • Estilos computados: el valor FINAL de cada propiedad tras cascada y herencia.
  • Selector de color y contraste: al editar un color, muestra la «rueda» y el ratio WCAG.
  • Modo dispositivo: emula anchos de móvil sin cambiar de equipo.
  • Probar selectores: en la consola, $$('.mi-clase') cuenta los elementos que coinciden (prueba de que el selector existe).

4. Método para encontrar el error de CSS

Cuando «no se aplica», en este orden:

  1. ¿Existe el elemento? Revisa el HTML y que la clase/id están escritas igual (mayúsculas).
  2. ¿Está correcta la sintaxis? Llaves abiertas/cerradas, propiedad: valor;, paréntesis de var().
  3. ¿Se carga la hoja? En «Red» o en la pestaña Estilos, mira si el .css se enlazó (ruta) y si aparece en «Sources».
  4. ¿La gana otra regla? En «Estilos», la regla tachada explica por qué: más especificidad o aparece después (cascada).
  5. Aísla: prueba con una sola regla sobre una clase nueva. Si funciona, el problema era el resto; ve añadiéndolo.

Este orden evita el «probando colores a lo loco» y convierte la depuración en lectura de evidencias.

Errores frecuentes y cómo corregirlos

  • Contraste insuficiente: usa el selector de color de DevTools y sube el ratio hasta al menos 4,5:1 en texto normal.
  • Animaciones sin respeto a prefers-reduced-motion: añade el media query con animation: none (y transition none si aplica).
  • Foco eliminado: nunca outline: none sin alternativa visible; estila :focus-visible.
  • Depurar a ciegas: primero aísla y confirma sintaxis; después, especificidad; al final, culpa a la hoja no cargada.

Ejercicios

  1. Fácil — medir contraste: inspecciona un párrafo de esta lección y comprueba en DevTools que el ratio cumple WCAG AA (4,5:1).
  2. Medio — movimiento reducido: crea una transición en un botón y añade el media query que la desactive si el usuario pide movimiento reducido.
  3. Difícil — depurar lo que no se aplica: escribe una clase .error-rojo que «no funciona» porque otra regla la gana por especificidad, y corrígela subiendo solo lo necesario. Explica el proceso con comentarios.

Soluciones razonadas

Intenta los ejercicios antes de leer esto.

Ejercicio 1

Texto oscuro sobre blanco supera 4,5:1. En DevTools, pon el cursor sobre el color en «Estilos»: aparece la rueda y el ratio. Si falla, oscurece el texto o aclara el fondo.

Ejercicio 2

button { transition: background 0.3s; }
@media (prefers-reduced-motion: reduce) {
    button { transition: none; }
}

Ejercicio 3

/* 1) p { color: #000 } y .error-rojo { color: #b00 } -> gana la clase.
   2) Si alguien pone #caja p { color:#000 }, gana por especificidad.
   3) Corrección sin !important: .caja .error-rojo { color: #b00; }
      Es más específica y respeta la cascada. */

La lección 03 explica por qué; aquí, el método: ver qué regla gana en DevTools y competir limpio con especificidad.
