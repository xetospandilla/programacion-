Lección 15: El modelo de caja

Todo elemento HTML es una caja: contenido, relleno, borde y margen. Entender esta «matrioska» explica la mitad de los problemas de maquetación.

Objetivos

  • Identificar las cuatro zonas de la caja: contenido, padding, border y margin.
  • Calcular cuánto mide de verdad un elemento.
  • Usar box-sizing para que la anchura incluya relleno y borde.
  • Controlar el desbordamiento con overflow.

Conocimientos previos

Las lecciones de introducción y unidades: aquí se usan px para que las cuentas sean evidentes.

1. Las cuatro zonas

De dentro a fuera: el contenido (texto, imagen...), el padding o relleno (espacio entre contenido y borde, fondo incluido), el border (borde visible o invisible) y el margin (espacio exterior, transparente, que separa de otras cajas).

/* diagrama conceptual, sin código */
┌────────── margin ──────────┐
│ ┌──────── border ────────┐ │
│ │ ┌────── padding ──────┐ │ │
│ │ │ contenido            │ │ │
│ │ └──────────────────────┘ │ │
│ └──────────────────────────┘ │
└──────────────────────────────┘

La caja de la demo (hoja externa) lo muestra con números:

.demo-caja .caja {
    width: 220px;
    padding: 20px;
    border: 5px solid #b5332e;
    margin: 10px;
}
Contenido (220px de ancho)

El padding (20px) es parte del fondo rosa; el borde (5px) lo rodea; el margen (10px) le separa de este párrafo.

2. ¿Cuánto mide de verdad?

Con el modelo clásico (content-box, el de por defecto), la width se aplica al CONTENIDO. El ancho total es:

ancho total = width + padding(izq+der) + border(izq+der) + margin(izq+der)

Con los números de la demo: 220 + 40 (padding) + 10 (borde) + 20 (margen) = 290px ocupa en pantalla, no 220. Este «desfase» es la causa número uno de cajas que se salen del contenedor.

Contra el margen se aplica además un fenómeno aparte: los márgenes verticales de dos cajas vecinas se colapsan (gana el mayor, no se suman).

3. box-sizing: incluir relleno y borde

Con box-sizing: border-box, la width prometida se cumple: padding y borde se restan por dentro en lugar de sumarse fuera. Compara las dos cajas:

.demo-caja .caja {         /* content-box (defecto): 220 + 40 + 10 */
    width: 220px; padding: 20px; border: 5px solid #b5332e; }
.demo-caja .box-border {   /* border-box: TODO en 220px reales */
    box-sizing: border-box;
    width: 220px; padding: 20px; border: 5px solid #2e7d32; }
content-box
border-box

Las dos declaran width: 220px; la primera ocupa 270px reales (sin contar margen) y la segunda, 220. La práctica habitual en proyectos es un reset global:

* { box-sizing: border-box; }

Así «220px» siempre significa 220px, y los cálculos se vuelven predecibles.

4. Desbordamiento: overflow

Si el contenido no cabe en la caja (texto largo, ancho reducido), desborda. Con overflow se decide qué hacer:

  • visible (defecto): el contenido se sale y se ve.
  • hidden: se recorta lo que no cabe.
  • auto: aparece barra de desplazamiento solo si hace falta.
  • scroll: siempre con barra.
Texto que desborda la caja porque no cabe en 160x40px.
Texto largo recortado por overflow hidden: lo que no cabe, no se ve.
Texto largo con overflow auto: puedes desplazarte para leerlo.

Errores frecuentes y cómo corregirlos

  • «Mi caja mide más de lo que puse»: es el modelo content-box sumando padding y borde. Usa box-sizing: border-box.
  • Margenes que «se comen» entre sí: es el colapso vertical: dos márgenes se funden en el mayor. Si lo sorprende, separa con padding en el contenedor o márgenes en un solo lado.
  • Contenido cortado de repente: revisa overflow: hidden heredado o una altura fija (height) demasiado justa.
  • Centrar con margin y que no funcione: margin: 0 auto centra solo cajas con ancho definido y display: block.

Ejercicios

Parte de mi-caja.html con su hoja mi-caja.css enlazada.

  1. Fácil — las cuatro zonas: una caja de 200px de ancho con padding 15px, borde 3px y margen 8px. Calcula a mano el ancho total y compruébalo.
  2. Medio — border-box: repite el ejercicio con box-sizing: border-box y anota la diferencia. Haz la cuenta antes de abrir.
  3. Difícil — desbordamiento: una caja de 120x50px con un texto largo y overflow: auto. Explica con un comentario por qué conviene auto y no scroll.

Soluciones razonadas

Intenta los ejercicios antes de leer esto.

Ejercicio 1

.caja {
    width: 200px; padding: 15px; border: 3px solid #333; margin: 8px;
}
/* total = 200 + 30 (padding) + 6 (borde) + 16 (margen) = 252px */

Ejercicio 2

.caja {
    box-sizing: border-box;
    width: 200px; padding: 15px; border: 3px solid #333; margin: 8px;
}
/* total = 200 + 16 (margen) = 216px; padding y borde van dentro */

Con border-box, la «promesa» de width se cumple siempre.

Ejercicio 3

.nota {
    width: 120px; height: 50px; overflow: auto;
    /* auto: barra solo si el texto no cabe, mantiene la caja limpia;
       scroll forzaría la barra siempre, aunque no hiciera falta. */
}

Resumen y autoevaluación

Toda caja tiene contenido, padding (por dentro de la caja), borde y margen (por fuera). En content-box la anchura declarada es solo el contenido; con box-sizing: border-box incluye relleno y borde. El contenido que no cabe se controla con overflow.
